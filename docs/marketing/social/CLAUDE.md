# Social Marketing Directory

Activity logs, post drafts, and screenshots for each platform Hexaverse gets
posted to. Mirrors the convention in Flywheel's `docs/marketing/social/` —
same account, same habits, different product.

## Structure

```
/social/
├── x/
│   ├── activity-log.md      # All posts, replies, engagement, learnings
│   ├── drafts/              # Post drafts before they go out
│   └── screenshots/         # Evidence — YYYY-MM-DD-<slug>.png
└── <platform>/              # Same shape when a new platform starts
```

Only `x/` exists so far. Add a platform directory when you actually start
posting there — an empty folder is a lie about where the work is.

## Activity Logs

Each platform has an `activity-log.md` tracking:

- Profile info and setup date
- Published posts with links and engagement
- Reply/comment activity
- Learnings (what's working)

**Always update the activity log after posting.** The numbers are point-in-time
— note the date they were captured, and come back a few days later to fill in
where they settled.

## Screenshots

Name them `YYYY-MM-DD-<slug>.png` so they sort chronologically. The screenshot
is proof; the *why did this land* guess in the log is the actual asset.

## Note on Flywheel vs Hexaverse

Both post from **@travis_flywheel**. Hexaverse posts are the side-project /
build-in-public content, Flywheel's are the product. Keep the logs separate —
what works for a space MMO demo is not what works for a data-pipeline pitch.
