## Why

`add-burn-cost-overlay` needs the burn quote to live in `SystemSpaceView` so the command panel and, later, the vitals strip read one quote and one request goes out per interval. Today the only production call site of `useBurnPreview` is inside `SpaceCommandPanel`, and that call site never enforces two request preconditions the live `system-space-view` requirement states or implies: no preview while a mine holds the movement channel, and no preview while the selected target is the fleet's own host (a zero-length solve the server answers with a 500). The lift must not carry those defects upward. This change is link 2a-ii of the system-HUD chain, split off `add-burn-cost-overlay` (its FULL-AUTO RULING 1), and narrowed by adversary round 1 to the lift and those two preconditions (FULL-AUTO RULING 16).

## What Changes

- `useBurnPreview` is called once, in `SystemSpaceView`; `SpaceCommandPanel` receives the quote by props and no longer imports the hook. The view derives "current quote" once and passes it down. A static guard keeps exactly one production call site.
- The view stops requesting a preview in three states, each as the view last read it: a running mine holds the movement channel (the view's existing `mineRunning` value, the same one it already hands the command panel for Burn's mine gate, so the two cannot disagree); the acting fleet is in lane transit (unchanged from today, carried through the lift); the selected target is the body, station or lane-gate body the acting fleet is attached to. Closes `drift-running-mine-preview-unsuppressed.md` and `defect-docked-selection-polls-zero-length-preview.md`.
- The requirement words the preconditions against the view's last read and states the lag: a state the view has not yet read (a newly acting mining fleet whose running-mine read has not answered, a failed read with no earlier answer, an attachment the own-fleets read has not yet reported) costs at most the requests sent until that read answers.
- A mine that starts while a preview is shown withdraws it, and it returns when the mine ends by its ETA or by cancellation. When a withheld state ends the preview is requested at that transition and presents nothing taken from before the withholding (no figure, ceiling or cap; a commit in the window carries no cap; a failed restoring request is a no-quote state, never a stale one), for every withheld state. A preview appearing, refreshing or being withdrawn is silent to assistive technology. No retry or re-quote path sends a preview request while the preview is withheld, and a cap rejection that lands while it is withheld re-quotes nothing and presents nothing for re-confirmation (`use-burn-preview.ts`).
- A withheld preview presents as neither a quote nor a failed quote: no figure, no no-quote state, no stale marking, no retry.
- The uncapped-burn label is not shown beside a burn command that is unavailable because nothing is selected, there is no acting fleet, the canvas is unavailable, or a mine holds the movement channel. This is the one false label the mine fix would otherwise leave on screen.
- The carried rationale "since a commit would be refused" is corrected: the mine and lane-transit suppressions are client request-suppression rules, not the server's enforcement.
- **The burn command's availability is unchanged in every state.** It is enabled or disabled exactly as today (no selection, no fleet, canvas unavailable, running mine); nothing here makes it newly unavailable, states a reason for it, or adds an accessible description. It stays enabled for a fleet attached to the selected target and for a fleet in lane transit, as today.
- **BREAKING:** none. Every presentation change withdraws something only where no preview is requested or the burn command is already unavailable, and no live requirement guaranteed it there: the live "preview SHALL be requested whenever a commit … would be accepted, and only then" already limited requests to accepted commits, and a zero-length burn is answered by the server with a 500, not accepted; the live "SHALL be labelled as uncapped before it is submitted" guarantees a label before a submission, which an unavailable command cannot make. Design.md records the reading.
- MODIFIED `system-space-view`, two requirements, each a complete replacement that carries every live scenario under its unchanged heading: "Burn Preview Reflects the Server-Solved Order, Without Committing" and "A Failed or Stale Preview Is Never Presented as a Current Quote". Three carried scenario bodies are edited and every other is byte-identical to live (design.md, "Carried scenario bodies edited"). The live sentence "SHALL clear … when an order commits" is carried unchanged and stays unimplemented: that drift is recorded in `docs/handoffs/drift-preview-does-not-clear-on-commit.md`.
- Test work: panel test harness migrated from a hook mock to props; seven wrong-shape `useBurnPreview` mocks in the view test files corrected; a static guard; view-level tests that observe every term of the call-site flag at the real call site, where it withholds and where it must not.
